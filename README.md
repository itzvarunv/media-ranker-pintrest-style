# Neuroed

A small image-curation web app with its own "semantic brain". Images and their
text captions are embedded into one shared 15-dimensional space (a CLIP-style
model). New uploads are sorted into niches by similarity, users get a
personalised feed, and uploads the model is unsure about are held back so new
niches can be discovered from them.

- **Niches today:** Aircrafts, Automotive, Fashion (50 images each in `vault/`)
- **Stack:** Python 3.13, Flask, MySQL, PyTorch (frozen ResNet18 + a small trained head)

## How it fits together

```
vault/  (image + caption pairs)
   │  train.py: contrastive training (image <-> caption words)
   ▼
encoder_weights.pth + semantic_brain.json  (weights, word vectors, one centroid per niche)
   │
   ├─► app.py (Flask) ── upload ─► classifier.py ─► best niche score
   │                                   ├─ ≥ 30 ─► live in that niche
   │                                   └─ < 30 ─► "Noise" (Pending, uploader only)
   │
   └─► discover.py ── groups the Noise pool ─► you approve ─► new niche
```

```bash
pip install flask mysql-connector-python bcrypt python-dotenv pillow torch torchvision numpy scipy
```

**4. Train the model once** (about 2 minutes on CPU). The first run downloads
the pretrained ResNet18 weights (~45 MB):

```bash
python3 "Failed mode/train.py"
```

> **macOS + python.org Python:** if the download fails with
> `CERTIFICATE_VERIFY_FAILED`, run `"/Applications/Python 3.13/Install Certificates.command"`
> once, then retry.

## Running

Always run from **this folder**. The scripts find `vault/` and the model files relative to it.

```bash
python3 app.py                       # web app on http://127.0.0.1:8080
python3 discover.py --dry-run        # preview new-niche proposals (changes nothing)
python3 discover.py                  # review and approve proposals
python3 "Failed mode/train.py"       # retrain (after adding data or approving a niche)
python3 "Failed mode/testing2.py"    # classify test_image_1..4.jpeg from the command line
```

## The web app

- **Accounts:** username + password (bcrypt). Password reset and recovery-email verification use a 6-digit
  code emailed to a **verified** address, expiring after 10 minutes and locked after 5 wrong tries.
- **Feed:** each post is served from one of three sources: a genre drawn by your interest points, a
  "discovery" post from outside your top genre, or something a peer liked. Likes, dislikes and saves move
  your interest points and the post's counters. Interest fades 1% per day.
- **Search:** matches words in titles and descriptions.
- **Upload:** pick or drag an image (JPG/PNG/WEBP, up to 10 MB), add a title and description. The model
  picks the niche. The image, a caption file and a `ranker` row are created, and it appears in your Saved tab.
- **Settings:** username, display name, password and recovery email all need your current password;
  the server re-checks it on every change. "Delete Account" is permanent and cascades to your history.
- **Security basics:** sessions are signed and `SameSite=Lax`, all queries are parameterised, `/vault/*`
  needs a login and serves images only, and uploaded files are re-encoded and size-limited.

## How classification works

- **Training** (`Failed mode/train.py`): a frozen ImageNet ResNet18 produces 512 features per image, and a
  small trained layer projects them to 15 dimensions. Caption words also get 15-D vectors (a caption is the
  average of its words). A CLIP-style contrastive loss pulls each image toward its own caption.
- **Niches** come from the `NICHE:` line in each caption. Each niche gets a **centroid**: the average
  15-D vector of its images, saved in `semantic_brain.json`.
- **Classifying** an image = the most similar centroid. The score (0–100) is the **confidence**.
- **Confidence cutoff:** below `CONFIDENCE_THRESHOLD = 30` (in `Failed mode/testing2.py`) the image is treated as
  Noise. On unseen images, wrong answers averaged 19–38 and right ones 56–61. A cutoff of 30 flags about 13% of
  genuine images, and 40 flags about 22%.
- Images labeled `NICHE: Noise` are never trained as a class.

### Vault format

Each image is `vault/<id>.jpeg` with a matching `vault/<id>.txt`:

```
ASSET ID: 0BK6N29
NICHE: Automotive
TITLE: One-line title
DESCRIPTION:
Free text describing the image.
```

To add a niche by hand: add 30-50 images with `NICHE: <name>` captions, add their `ranker` rows,
and run `train.py`.

## Discovering new niches

`discover.py` is the image version of the earlier text `scanner.py`. It works on the **Noise pool**: uploads the
classifier wasn't confident about, stored with `genre = 'Noise'` and `status = 'Pending'`.

1. **Words:** a word that appears in at least 5 pool posts and is 10× more common there than in the rest of
   the vault seeds a group (this finds brand/person niches like "Verstappen").
2. **Looks:** the remaining posts are clustered on a blend of image and caption similarity (groups need at
   least 8 images).
3. **Naming:** signature words are those common inside a group and rare outside, graded 3/2/1.
4. **Warning:** if most members already classify into one niche, it says the group is a *sub-niche* of it.
5. **Approval:** answer `y`, `n`, or type your own name. On yes, the posts move out of Noise, their caption
   `NICHE:` lines are rewritten, and a centroid is added so the running app classifies the new niche immediately.
   Run `train.py` afterwards to train it properly.

## Settings you can tune

| Setting | File | Default | Effect |
|---|---|---|---|
| `CONFIDENCE_THRESHOLD` | `Failed mode/testing2.py` | 30 | Below this, an upload becomes Noise |
| `MIN_CLUSTER_SIZE` / `LOOK_MIN_SIZE` | `discover.py` | 5 / 8 | Images needed for a word-group / look-alike group |
| `MIN_LIFT` | `discover.py` | 10 | How over-represented a word must be to seed a group |
| `INTEREST_POINTS` | `feed.py` | like +10, dislike −10, save +5 | How fast a user's taste moves |
| `MAX_UPLOAD_BYTES` | `vault.py` | 10 MB | Upload size limit |
| `OTP_LENGTH`, `OTP_TTL_MINUTES`, `OTP_MAX_ATTEMPTS` | `Settings.py` | 6, 10, 5 | Email-code rules |

## Known limitations

- **Discovery only sees uncertain uploads.** A photo of a new driver or brand inside an existing niche
  (e.g. an F1 car) will usually score above the cutoff and go live in its parent niche, so it never reaches
  the pool. A second trigger based on caption words in recent live posts is not built yet.
- **A new sub-niche can pull in similar images from its parent.** In a test, retraining with a new "Porsche
  Racing" niche made an unseen Lamborghini photo classify as Porsche Racing. There is no parent/child hierarchy.
- **The 30 cutoff won't catch off-topic images that resemble a niche.** A movie poster scored 38. Retune it after retraining.
- **Word-based discovery needs the word in the captions** of at least 5 uploads.
- **Pending posts that never form a group stay Pending forever.** There is no expiry or manual assign.
- Reloading the feed shows new posts, because served posts count as seen. It recycles old posts once
  everything has been seen.
- Uploads are labeled by the model's own guess, so a later `train.py` run trains on those guesses.
- There are no automated tests in this folder, and no login rate limiting.
- The dev server (`app.run`) is not for production use.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Vault folder 'vault' not found!` | You're not in this folder. `cd` here first |
| `FileNotFoundError: 'path/to/vault/test'` | You ran the unused top-level `test.py`. Run the commands above instead |
| `CERTIFICATE_VERIFY_FAILED` while downloading weights | Run `Install Certificates.command` (see Setup, step 4) |
| Uploads say "The classifier isn't ready" | Run `train.py` first so `encoder_weights.pth` and `semantic_brain.json` exist |
| No emails arrive | Check the `MAIL_*` values and use a Gmail app password. The error prints in the terminal |
| Everyone gets signed out on restart | Set `SECRET_KEY` in `.env` |
